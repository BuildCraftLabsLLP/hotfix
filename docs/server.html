How it works

A background service that never gets bored.

It runs as a system service (systemd, a Windows service, launchd) from boot and watches every user's processes.

Watches

Every 5 seconds it measures every process's CPU, for every user, as a percent of one core.

Decides

A process above your threshold (90% by default) for your duration (5 minutes) is a runaway, unless it's a protected system service, on your whitelist, or owned by a user you protect.

Acts

It kills the runaway (a gentle stop first on Linux and macOS) and tells you: in its log, in hotfixd status, and through an optional webhook to Slack or anything else.

Safe by default

Built so it won't be the outage.

Starts by watching

A new install only reports what it would kill. Tune it with hotfixd check, then turn killing on with one command.

Never touches the essentials

The kernel, init, sshd, journald, container runtimes, package managers mid-upgrade, Windows' core services and itself are always off limits.

Knows when to stop

If something keeps restarting, it backs off after three kills an hour instead of fighting your service manager forever.

Questions

Before you install.

Will it kill my database or my build?

Not on its own: it starts in monitor mode and only reports. Before switching to enforce, run hotfixd check and protect what's allowed to be busy: protect_users (e.g. postgres), the whitelist, a higher cpu_threshold or a longer kill_duration. CPU is measured per core, so on a 32-core box a threshold of 90 means "90% of one core".

What counts as a server?

Each machine running hotfixd with your key holds one seat. Seats are leases renewed every few hours, so autoscaling groups and retired machines free their seats by themselves; you can also release one on the manage page. For images, set license_key_file or HOTFIXD_LICENSE_KEY and new instances activate themselves on first boot.

What if the server is offline?

Its license stays valid for 7 days without contact; it keeps protecting the server meanwhile. If the license lapses, hotfixd keeps watching and reporting but never kills.

Does it work in containers?

Install it on the host: it then sees and protects every container's processes too (and can skip them with skip_containers). Inside a container it can only see that container.

What does it send?

Only license checks: an anonymous hash of the machine ID, the hostname, OS and hotfixd version. Nothing about your processes ever leaves the server, except what you send to your own webhook.

Is it open source?

The code is public on GitHub under the Elastic License 2.0: you can read, audit and build it, but not remove the license check or resell it as a service. The desktop apps stay free and MIT-licensed.
